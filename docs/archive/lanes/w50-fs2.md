## 2. AMENDMENT (i) — THE DECISION, AND WHY THE ALTERNATIVES ARE WORSE

**Chosen: `compose_prompt` grows a third return value.** `(prompt, claim)` → `(prompt, claim, mail)`.

```python
def compose_prompt(name, cwd, task, sid, journal_path=None,
                   context=None) -> tuple[str, Path | None, str]:
    ...
    claim = None
    mail = ""
    if sid is not None:
        mail, claim = claim_mailbox(sid)
    ...
    return "\n".join(parts), claim, mail
```

The resume arm then inlines **the drained mail itself**, not a constant:

```python
    prompt, claim, mail = compose_prompt(name, cwd, "", old_sid, journal_path=journal_path)
    ...
        inline_kind="resume", inline_body=mail,
```

### Why not "the call site claims the mailbox itself" — the brief's other named option

This is the option I rejected hardest, and not on taste. `compose_prompt` is the **sole** claim
point, and its own docstring states the reason: *"the universal-drain guarantee holds (every
compose_prompt call claims the mailbox)"*. A second claimer costs four separate things, all
measurable in the tree rather than hypothetical:

1. **The drain event moves or doubles.** `compose_prompt` emits `mail_drained` at the moment of
   the claim (`bin/fleet.py`, the `append_event("mail_drained", ...)` line inside the `if mail:`
   arm). `tests/test_resilience.py::test_compose_prompt_drain_emits_mail_drained` and
   `::test_compose_prompt_no_mail_emits_no_drain` pin exactly that pairing. A call site that
   claims first would either emit the event twice or move it away from the drain.
2. **The `<MANAGER MESSAGE>` framing gets a second author.** `tests/test_index_compose.py`'s
   composition-order test pins preamble → digests → mailbox → task → journal. Formatting the mail
   at a call site duplicates that formatting and lets the two spellings drift — and
   `test_index_compose.py` explicitly warns that *"a self-comparison only pins that the two
   spellings agree"*.
3. **Two claim/restore/finalize paths on one sid.** The launch-sequence contract is
   claim → dispatch → `finalize` on success, `restore` on failure. Two claims mean two claim
   Paths, and the failure path has to restore both in the right order or lose mail. That is a new
   correctness surface on the *unattended* verb.
4. **It would have to pass `sid=None` to skip the second claim** — which is the documented shape
   for *a fresh native spawn that has no sid yet* (M-B T4). Reusing it for a resume would make the
   record lie.

### Why not "read the mail back off the returned claim Path" — the option the brief did not name

This is genuinely tempting and I want it on the record that I considered it, because it has zero
caller churn: `claim` is a `Path` to `mailbox/<sid>.md.claimed.<pid>`, the file still exists when
`dispatch_bg` is called, and `restore_mailbox_claim` **already** reads it (`claimed =
claim.read_text(...)`), so the precedent is in the same module twelve lines away.

**I rejected it because it creates a second copy of the truth that can silently diverge.** The
prompt would carry `mail.strip()` from memory while the inline carried a fresh disk read; today
those are identical, and they stop being identical the first time anyone caps, redacts or
normalises the mail inside `compose_prompt`. This repo's named recurring defect is *one identifier
doing two jobs* — `docs/lanes/w49-fs.md` §1a re-derives it one level down for the payload file —
and "two reads of one fact that are equal by coincidence" is the same class. A third return value
has one source: the caller inlines **the same string object** the function embedded. There is a
test that says so out loud:

```python
    assert mail in prompt, (
        "the returned mail is not the text that went into the prompt -- two "
        "copies that can disagree is exactly what this return value exists "
        "to prevent")
```

### The cost I am accepting, stated plainly

18 unpacking sites edited, 14 of them one-token test edits (`prompt, claim =` →
`prompt, claim, _mail =`). **It adds no lines to `bin/fleet.py`'s call sites**, which is why the
citation cost of the decision is zero — the +117 net lines are the `dispatch_bg` inline block, the
two constants and their comments. `tests/test_index_compose.py`'s call-site census
(`test_the_compose_census_is_exhaustive`, keyed on the SET of caller functions) is unmoved,
because no call site was added or removed.

### One thing I changed that the brief did not ask for, and why

At the **send** arm §6e passes `inline_body=message`. I pass:

```python
    inline = mail if (mail and len(mail) <= NATIVE_INLINE_STEER_MAX) else message
```

Reason, and it is not cosmetic: `mail` is `message` **plus anything already queued** — including a
residual that a previous steer's `_migrate_residual_mailbox` parked on this sid. Inlining the drain
delivers both. But the cap truncates **head-first** and `message` is the mailbox's **tail**, so
over the cap, inlining the whole drain would cut away the very steer `send` is about to print
success for. Take the drain when it fits, fall back to `message` when it does not: **never fewer
guarantees than §6e, usually more.** The `mail`-empty fallback matters too — `claim_mailbox`
swallows `OSError` into `("", None)`, and a failed mailbox read must not silently un-deliver the
steer.

## 3. AMENDMENT (ii) — TWO ARMS, TWO SENTENCES, AND A PIN THAT REFUSES ONE

§6e's wrapper reads *"That message is a NEW instruction and it supersedes anything earlier in this
session."* For `send` that is exactly right. For `resume-limited` it instructs an unattended worker
to abandon the task the resume exists to finish.

`dispatch_bg` now takes `inline_kind` and selects the framing itself, from a module constant:

```python
NATIVE_INLINE_LEAD = {
    "steer": ("That message is a NEW instruction and it supersedes anything "
              "earlier in this session."),
    "resume": ("Your previous turn was cut short by a usage limit, whose reset "
               "horizon has now passed. CONTINUE the task you were already "
               "working on -- nothing here replaces it, and anything above is "
               "further instruction for that same task."),
}
```

`inline_kind` rather than the caller passing prose, deliberately: the wording is the thing that
must not be shared, so it lives in one greppable place and the call sites carry only which of the
two they mean. An unrecognised kind **raises** rather than falling through to an un-inlined turn —
a typo would otherwise silently restore the exact defect the parameter removes, on a path whose
other tests all still pass. That is pinned
(`test_an_unrecognised_inline_kind_is_a_loud_error`) and fault-injected (M7, §5).

**The pin for the property itself is DRIVEN, not constant-comparing.** `assert
NATIVE_INLINE_LEAD["steer"] != NATIVE_INLINE_LEAD["resume"]` would be the obvious test and it is
the weak one: it dies the moment someone refactors the dict away, and it says nothing about which
call site gets which. Instead
`test_the_steer_and_resume_arms_do_not_share_one_wrapper` drives **spawn → steer → park →
resume in one fleet home**, subtracts the spawn turn (the bytes the session has already answered)
from each of the two later turns, and asserts on what is left:

* both wrappers non-empty — so no assertion below can pass vacuously;
* `steer_w != resume_w` — **the collapse this test exists to catch**;
* `"supersede" in steer_w`, `"supersede" not in resume_w`, `"continue" in resume_w`.

It also subtracts the operator's own message before asking those questions, because the fixture's
`STEER` constant itself contains the word *"superseded"* — without that subtraction the steer
assertion would pass on a wrapper that said nothing at all. **A test that reds only because of its
fixture's prose is not a pin**, and I only noticed on re-reading my own first draft.

## 9. THE OVER-LENGTH HOLE — LEFT OPEN, DELIBERATELY, AND NOW PINNED

The brief asked me to decide whether §6b's residual is in scope. **It is not, and I am leaving it
open.** Saying so is the point of this section, because an inherited known hole that goes
unmentioned reads as fixed.

**What the hole is.** A message longer than `NATIVE_INLINE_STEER_MAX` (4000) is truncated in the
turn with a marker naming the file. For those messages the guarantee degrades to exactly SHAM-2:
the turn is distinguishable and says the file was rewritten, so the tail arrives only if the worker
chooses to re-read. `w49-fs` §6b calls this *"a real hole in my own fix"* and it is right.

**Why I am not closing it.** Closing it means composing FIX-B onto the overflow — hand the turn a
payload identity the session has never dereferenced. That changes `task_file_path`'s identity, and
`task_file_path` has **4 callers**: `_recovered_brief`, `_remove_worker_files`,
`_archive_file_pairs`, `dispatch_bg`. Cleanup and archive would both have to learn to glob, and
every unswept dispatch would leave a file behind. Three sibling lanes are editing `bin/fleet.py`
this wave and my brief fences me to `cmd_resume_limited` / `cmd_send` / `compose_prompt` /
`dispatch_bg`. It is a second patch, and it is not this one.

**What I did instead — the hole is now pinned rather than described.**
`test_an_over_length_steer_rides_the_turn_only_as_far_as_the_cap` asserts the head reaches the
turn, the turn **says** it was cut, the tail does not reach the turn, and the tail is still
reachable behind the pointer. Mutant M6 (§5) removes the truncation marker and the pin reds. So the
degradation cannot silently get worse, and a future lane that raises or removes the cap has to
touch a test that names this report.

**One measurement I am NOT making a recommendation on**, because it is a judgement outside my
fence: the cap could be raised substantially — the Win32 command-line limit is 32767 characters
and the rest of the dispatched argv is a few hundred — which would shrink the hole a lot without
closing it. I did not change the constant, because 4000 was a deliberate choice by the lane that
measured the path and "raise it and see" is not evidence. §12 routes it.

**And the hole now applies to the unattended arm too.** With the mail inlined, a >4000-character
queued message truncates on `resume-limited` as well. That is strictly better than §6e (where the
mail was not inlined at all, at any length) and it is worth naming, because the resume arm is the
one with nobody watching.
