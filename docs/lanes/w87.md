## Part 2 — the two no-handoff cuts, landed and pinned by tests

1. **Wake resumes, never forks** (`bin/fleet.py` `_wake_supervisor_native`). An idle
   supervisor's `fleet send` wake now dispatches fresh (no `--resume`) instead of forking the
   transcript; the fresh body proves continuity to `sup-boot` via a minted nonce, which restamps
   the SAME incarnation_id — no new generation. Ordinary worker steer is unchanged (still the
   ratified G2b fork-steer). MEASURED cost of the old behavior: a6c9's 4 retired fork-parent
   transcripts total 7,553,045 bytes (76.4% of that generation's 9,881,553 on-disk bytes).
2. **Successor boot is already checkpoint-only.** `cmd_sup_handoff_begin` already dispatches
   fresh (`--bg`, no `--resume`/`--fork-session`), and `sup-boot`'s boot bundle only reads GOALS
   + journal tail + knowledge index + fleet status, never a transcript — no code change was
   needed; added the pinning test that was missing.
Tests: 7 new (`tests/test_supervisor_wake.py`) + 1 new pin (Cut 2, `test_supervisor.py`) + 2
updated pre-existing (`test_wake_retirement.py`, which pinned the old forked behavior) + 6
census tests extended for the new dispatch/render sites. Green on py3.10/py3.12 (2536/2535
passed, 11 pre-existing skips, 0 failed).
