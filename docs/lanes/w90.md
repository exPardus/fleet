# w90 — cut what a supervisor boot reads

DONE means: the supervisor boot bundle is measured input-by-input in tokens, the largest inputs are cut so that a boot reads a capped checkpoint and pointers rather than whole journals, and the cap is pinned by a test that fails if the bundle grows past it.
Full measurement table, method, rationale: `docs/lanes/w90-report.md`.

## Measured (this repo's own supervisor files, 2026-09-16)
`_render_boot_bundle()` = 12,271 bytes / ~3,068 tokens before this lane. GOALS.md (7,056B, 57.5%)
+ old journal tail (3,526B, 28.7%) = 86.2%, confirming the brief's suspicion for the tail.
GOALS.md is large but operator-owned, not unboundedly growing, spec-required in full every boot —
**left uncut**, reported not silently skipped. The journal tail *was* byte-unbounded:
`SUPERVISOR_BODY_MAX_LINES` caps newline count (3), not per-line length; non-checkpoint kinds
carry no cap at all.

## Cut
Only the newest of the last 5 tail entries inlines its body; older entries become one-line
pointers ("full text: supervisor/JOURNAL.md"). Newest entry also capped at
`SUPERVISOR_LATEST_ENTRY_MAX_CHARS` (2,000 chars, truncation pointer). Lost: prose of
checkpoints 2-5 back, never timestamp/kind/inc/sid — one `cat` away. Saved on this repo's real
(non-pathological) journal: 1,922 bytes / 480 tokens, 15.7% — the real value is removing the
unbounded ceiling, not this one number.

## Cap
`SUPERVISOR_BUNDLE_MAX_CHARS` existed (40,000, whole-bundle backstop) with zero test coverage.
Lowered to 20,000 (~2x measured post-cut bundle), pinned by
`tests/test_boot_bundle_cost.py::TestBundleByteBudget`. Today's real bundle violates neither cap
— the finding is the missing test, not a status-quo breach.

## Scope held
In: `_render_boot_bundle`. Out (per brief): handoff verbs, band numbers, spawn prompts, `fleet
send` — untouched.

## Tests

suites re-run clean both interpreters. Full floor: `docs/lanes/w90.json`.
