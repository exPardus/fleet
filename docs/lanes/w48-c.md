### 0d. What I did NOT build — ESCALATED to the operator

## 1. (c)(i) — hook argv

### 1a. The dispatch surface

`worker-settings.template.json`, all four hook commands, now:

    "\"{{PYTHON}}\" \"{{FLEET_INSTALL}}/bin/hooks/<hook>.py\" --fleet-home \"{{FLEET_HOME}}\""

**`render_worker_settings_template` was not touched.** `{{FLEET_HOME}}` already substituted; the
slice needed the template to *use* it. Slice 0 finding 4 therefore holds by construction —
`fleet_install` still defaults to the home, both placeholders stay legal, and an out-of-tree
template written against `{{FLEET_HOME}}` still renders byte-identically. Pinned by
`test_the_legacy_placeholder_contract_is_untouched`.

Forward slashes and quoting (root `CLAUDE.md`): `{{FLEET_HOME}}` renders through
`Path(...).resolve().as_posix()` and the value is double-quoted inside the command. Driven against
a home literally named `a home with spaces`.

**Both `--settings` sites are covered by one edit — which is why the spec bundled this slice.**
MEASURED: the worker dispatch resolves `settings = Path(settings_path) if settings_path else
instance_settings_path()`; the successor dispatch names `instance_settings_path()` directly. And
`instance_settings_path()` is `<home>/state/worker-settings.json` — **home-relative**, so
`fleet init` already renders one instance per home and the bake is per-home for free, exactly as
the spec's `**Hooks**` line asks (*"argv baked per-home … both `--settings` sites"*). The manager's
steer that these are one mechanism with two dispatch callers is confirmed, and this is the
mechanism.

### 1b. The dispatched plane

Each hook gains `_ARGV_HOME_FLAG` + `_argv_fleet_home()` and an ordered `_fleet_home()`. **No
cross-module import was introduced** — the four stay textually independent per `stop_outcome.py`'s
doctrine, and the *behavioural* agreement test grew a second axis instead
(`TestTheFourStillAgree`, including agreement with `fleet.py`'s own `strip_global_fleet_home`).

| §5 step | in a hook | why |
|---|---|---|
| 1 `--fleet-home` | **NEW** | the baked argv IS the flag |
| 2 sid→lookup | skipped | one registry read per listed home, per tool call |
| 3 validated env | kept, unchanged | `FLEET_HOME` stays a **working** input |
| 4 legacy install root | kept, unchanged | the `__file__` fallback |
| 5 terminus | skipped | its content is *"mutating verbs refuse"*; invariant 2 is exit-0 hooks |

**Grammar matches `strip_global_fleet_home` deliberately** — `--fleet-home V`, `--fleet-home=V`,
`--` ends options — because both consume the same option string, and a hook that disagreed with
`fleet.py` about its own flag's spelling would be drift by construction.

### 1c. Two design calls that could have gone the other way

**An argv home is NOT validated.** §5 step 1 validates (`is_dir`, initialized) and lets a mutating
verb refuse. A hook has no refusal. If it validated and fell through on failure, a broken bake
would be silently traded for **a write into the donor's home** — the exact incident class the
fence closes. So a present, non-empty value wins outright; a failed write stays a logged, exit-0
event *in the home the dispatch named*. Pinned by `test_an_unvalidated_home_is_still_the_answer`.

**A repeated flag with two different values returns `None`** (falls to step 3) rather than picking
one. `fleet.py` refuses it (*"One invocation names one home"*); a hook cannot refuse, so it
declines the contradictory input. Same decision, tiered by what the plane can do.

### 1d. The exit-0 invariant, and an asymmetry the brief did not mention. MEASURED.

**The four hooks are not equally netted.** `bin/hooks/stop_outcome.py`'s entrypoint is a bare
`sys.exit(main())` with **no `except`**, and it calls `_fleet_home()` **above** its own inner
`try`. The other three wrap `main()` in `except Exception` and `sys.exit(0)` unconditionally. So a
raise inside `_fleet_home()` reaches the session as a traceback from exactly one of the four — the
one whose call site is outside the net.

`_argv_fleet_home` is therefore written so it cannot raise: every operation is a bounds-checked
index or a `str` method on a `sys.argv` element. And it is **driven, not read** —
`TestHostileArgvNeverRaises` runs all four hooks end to end (real argv, real JSON on stdin) over
seven hostile shapes: trailing valueless flag, unknown flag, flag-eats-a-flag, empty `=` value,
bare positional, embedded newline, 5000-char value — asserting rc 0 and no `Traceback`.

## 8. The self-citation tax — MEASURED: twelve, not forty and not zero

`bin/fleet.py` 21,447 → 21,533 lines (+86). **12 rewrites across 9 distinct cited line numbers,
0 refusals.**

Method, and it is not "add the delta":

- old→new map by **difflib** against `fa236cb`'s own blob (alignment covered 21,433 of 21,438 base
  lines; the five unaligned are the lines this change edited, and no citation pointed at any of
  them — hence zero refusals).
- **every rewrite content-verified**: `old_lines[cited-1]` must equal `new_lines[mapped-1]`, else
  REFUSE and report. The script exits non-zero on any refusal rather than writing a partial repair.
- **which numbers are self-citations is decided by the suite's own classifier**
  (`tests/test_self_citations.py`'s `_in_prose` + `_document_prefixed`), applied **per match, not
  per value** — two prose numbers can share a value while only one is a self-citation, and a
  value-keyed filter would rewrite both.
- **ranged forms handled explicitly.** A range END has no colon before it, so `:(\d+)` is blind to
  it; `` `(\w+):(\d+)-(\d+)` `` is scanned separately. (In this file at this commit the range ends
  needed no rewrite — but they were *checked*, which is the point.)
- **fixpoint:** the pin files ran clean on pass 1 and were re-run three times consecutively, all
  green. Repairing the whole derived population rather than the reported failures is what buys
  that.

### A CRLF hazard the tool would have caused, caught before it applied. MEASURED.

`bin/fleet.py` is pure CRLF (21,447 of 21,447 newlines). The scan ran on `Path.read_text()`, which
decodes with **universal newlines** — one byte shorter per line. The first apply asserted the text
at each offset equalled the number it was about to replace and hit `'IS LI'` at offset 842763,
roughly 250 lines past the citation it meant to fix. Offsets are now translated exactly
(`offset + count of '\n' before it`, sound because the file has no bare LF), and both the total
CRLF count and the no-bare-LF property are asserted before the write. Without that assert this
would have been twelve silent corruptions inside a file whose diff nobody could then read.
