# Lane w89 — the reaper's lane arm has never fired

DONE means: a landed/abandoned lane row is reaped by the lane arm on the
next boot/wave close, pinned by landing a real lane through `fleet land`
and showing reap reason `lane-landed`/`lane-abandoned`. Full detail:
`docs/lanes/w89-report.md`.

## Design: (b), wave-close is the writer

`fleet_land.py` deliberately has no fleet-kernel dependency; `cmd_land`
never resolves a fleet home (pinned by
`test_parser_registers_land_and_dispatches_without_home_resolution`). From
a bare worktree `FLEET_HOME` is unset, so `fleet_lock()`/`registry_path()`
would hit the worktree's own nonexistent `state/` — land cannot safely take
the lock. `wave-close` already holds `fleet.lock` and already computes
`_wave_landed_lanes`, so it writes `lane_state=landed`, joined
lane→worktree→registry record by `cwd` (same join `_wave_record_substrate`
uses). No predicate change: `_reap_eligible` already read `lane_state`.
