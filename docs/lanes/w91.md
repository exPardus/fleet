# w91 — a verb that cannot measure must not publish a measurement

DONE means: `wave-close` never publishes `MEASURED` on a lane count it could not derive, reporting unparsed merges instead and refusing when the range holds merges it cannot attribute; `fleet land` enforces the same docs-currency rules the wave floor does; and the `merge(<lane>):` convention is stated where a supervisor reads it, all three pinned by tests. Full detail, rationale and replay commands: `docs/lanes/w91-report.md`.

## A. `wave-close` refuses an unattributable range

`_wave_landed_lanes`'s regex silently dropped any merge whose subject was
not `merge(<lane>):` -- git's own default subject included -- so every
downstream figure read as a confident, unmeasured zero. New
`_wave_merge_audit(repo, base, run)` returns `(lanes, unparsed)`;
`cmd_wave_close` raises `FleetCliError` naming `UNPARSED: N of M` + SHAs
the moment `unparsed` is non-empty -- before the claim, reap, floor, and
every mutation. A genuinely empty range still closes clean.

## B. Convention stated where read

`skills/fleet/SKILL.md`'s Wave boundary section states `merge(<lane>):
<summary>`; `fleet land`'s GREEN output prints the exact next merge
command.

## C. `land`'s docs-currency parity with the floor

`tests/test_docs_currency.py`'s `__main__` (shelled by `fleet_land.py`, no
pytest dependency) now also runs `test_new_lane_documents_have_done` and
`test_dispatched_tasks_have_done`, not just `currency_violations` -- the
w90 gap.
